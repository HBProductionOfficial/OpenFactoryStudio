# Changelog

What changed in each version.

## Version 1.1.2 (9 November 2026)

### Added

- The mouse wheel zooms the Offset viewer and the Throw creator, one step per notch, with the origin staying in place as in Fighter Factory.

### Changed

- The help pages, the state controller templates and the new character template use American spelling, like the rest of the program. MUGEN's own names keep Elecbyte's spelling, so DefenceMulSet stays as it is.

### Fixed

- When the Sounds editor opens, the first sound fills the width. Before, it often took up only a small part of it.
- Increase zoom, Decrease zoom, Actual size and Fit screen size work in the Sounds editor and in the emulator. In the Sounds editor they step like Fighter Factory's: by hundredths up to 0.1 pixel per sample, then 0.15, 0.2, 0.25, 0.5, 0.75 and whole pixels from 1 to 32.
- In the Sounds editor the wheel and the zoom buttons stop where Fighter Factory's do. Zooming in ends at 32 pixels per sample, and zooming out at a third of the fitted size (0.02 pixel per sample at the least).

## Version 1.1.1 (8 November 2026)

### Changed

- Ogg Vorbis sounds are read with libvorbis, the library that already saved them. stb_vorbis is gone.

### Fixed

- SFF files where a sprite links to a sprite that comes after it open the way they look in Fighter Factory.
- Damaged sprite and sound files open. The sprites and sounds that can be read are there, and the Issues panel lists what was wrong with the others. Files the project names that aren't on disk are listed there too.
- File names that a game file writes with backslashes or in another letter case are found on Linux.
- Run in engine works for a character in a folder with a space in its name.
- Run in engine copies only the sprite and music files of a stage, and only into the engine folder. Before, a stage could name any file, even a program library, and it was copied next to the engine.
- Names in game files that point to another computer (`\\server\share`) aren't opened, and neither are Windows shortcuts, which can point to one. Windows would sign in to that computer. The Issues panel lists them.
- Lua scripts and presets load only source code. A preset that runs too long is stopped, so it can't hang the program at start.
- A sprite or sound file whose entries point to the same data many times can't use up the memory, and neither can a tiny sprite that claims to be huge. Archives that unpack to more than 50 times their size (2 GB at least) aren't unpacked.
- Archives can't put files outside the folder they are unpacked into, also on Linux, where letter case matters.
- Text from game files shows as written in messages and tooltips, also when it looks like HTML.
- The update check only opens this project's release page.
- The About box shows the GPL terms only, without the part at the end that is a template for authors of other programs.

## Version 1.1.0 (1 November 2026)

### Added

- Tooltips like Fighter Factory's. Buttons show their long description without the shortcut, and the check boxes in the panels show their caption. The palette grids show the color under the pointer as R, G, B, A, and resting on an underlined word in the code editors shows its issue. The Issues tab tells how many errors or warnings there are. Code trees, debug variables and Advanced Search results show their own text, which helps when it's cut off.
- Mouse pointers like Fighter Factory's. The graphic workspaces show an open hand where a drag moves the view, and the hand closes while you drag. Things you can drag, like the sprite or a contact box, show the four-way arrow, and guide lines and box handles show resize arrows. The image editor hides the pointer for its drawing tools and marks the pixels under the brush instead. The sound tools have their own pointers, and in the code editors the pointer hides while you type.

### Changed

- A drag that starts on the rulers moves the view, and dragging on the timeline goes through the frames. The Offset viewer and Throw creator can be moved around with the mouse.
- Paths in tooltips use forward slashes, like Fighter Factory.

### Fixed

- The sprite is drawn with the palette chosen in the Palettes panel, in the Sprites editor and in the image editor, also with Switch to the sprite palette on. Saving the image keeps the sprite's own palette.
- Remap pen: the right and middle buttons paint the pairs the other way round, and a slot with only the color to replace makes it transparent. Its slot bar draws each cell apart, like Fighter Factory's.
- Palette edits made while the image editor is open keep the changes on the canvas. The paint bucket fills with any mouse button, and Move selection moves with any button.

## Version 1.0.0 (6 October 2026)

The first full release. It has all the editors and tools of Fighter Factory Studio 3.7 for M.U.G.E.N with their options, and the emulator with its debugger. Projects can also be debugged in WinMUGEN. There are downloads for Windows, Linux and macOS.

### Added

- Animations editor: the current frame is drawn over the timeline with its sprite, offset, flip, scale and angle, along with the player axis, the frame offset (secondary cross), the extra cross, rulers and guide lines. Dragging the sprite moves the frame offset. The panel edits the animation's number and name and the frame's sprite, offset, time, flip, transparency (with source and destination), loop start, scale, angle and interpolation, and can show an onion skin frame from any animation.
- Contact boxes: you draw them in a drawing mode that stays on until you right click. They can be selected, moved, resized by their handles, nudged with the arrow keys, deleted, switched between attack and collision and between regular and default, copied from the frame before, copied to every frame with the same sprite, and cut, copied and pasted. Default boxes show on the frames that use them, in the engine's default colors.
- Animations menu: New, Open, Add (with name, number and time), Delete, Duplicate (with a new number if you want), Add and Delete frame, Apply offset, time, flip, transparency and scale to all next frames, the Alignment Tool (offsets, box resizing and scaling for the animations you pick), Optimize, Play and Stop (60 ticks a second, looping at LoopStart, holding endless frames, with interpolation), Edit code (the whole file in the code editor, with the current animation and frame following the cursor), Edit animation code (one animation in its own window) and Save as animated GIF (scale and speed). The Sprite explorer adds frames to the current animation or makes new animations from a group's sprites.
- Every change made in the visual editor only rewrites the lines it touches, written the way Fighter Factory writes them, as one undo step in the text it shares with the code editor.
- Sprites > Switch to the frame's sprite: the Sprites editor shows the sprite of the current frame in the Animations editor.
- States > PalFX editor: shows a PalFX controller's values on the project's sprites (with the sine moving), loads templates from the palFX folder, and Insert puts it in the editor.
- Issues lists the lines in animation files that can't be read.
- Sounds editor: the current sound's waveform (one band per channel, a time ruler in ticks, the cursor and the selection) with six tools (Move view offset, Zoom, Free selection, Move selection, Horizontal and Vertical resizer). The panel has the sound selector, group, index, the sound's format and length, the volume, the current sample and the selection. Waveform changes (Remove selected, Fill silence, Fade in, Fade out, Cut, Copy, Paste and the move and resize tools) wait until Save changes, which makes them one undo step. Discard changes throws them away, and leaving the sound or the editor with changes waiting asks first. Play, Play with loop, Pause and Stop start from the cursor, and the status bar shows the cursor, the selection and whether it's playing.
- Sounds menu: New, Open, Save as, Add (numbers from the file names or counting up), Delete, Duplicate, Change sound, Save sound as (WAV, OGG or FLAC), Resample (channels, rate and bits for the sounds you pick), Delete group, Rename group, Export (FFE and SndMaker lists with the WAV files) and Import (FFE, asking what to do with numbers already used).
- Palettes panel (on the right of the Sprites editor): the palette selector, Switch to the sprite palette, group and index, and the palette grid (select with click, Ctrl+click and Shift+click, double-click to edit a color with alpha, drag a color onto another slot). Palettes menu: Add (from palette files, or an empty 32-color palette), Delete, Remove all duplicates, Clear all unused, Clear, Change (ACT, PCX, PNG, GIF, BMP, PAL, ACO, ASE and Corel Painter swatches), Save as (ACT), Switch color count (32 and 256, and the colors come back), Exchange position of selected colors, Set the color of the selected slots, the Color picker, Apply to the sprites and the Remap tool. Palette color changes are undo steps of the sprite file, and Palettes > Undo and Redo reach them too.
- Advanced palette editor (Tools menu): the current sprite from the Sprites editor with its palette, next to a free image and palette, each with its own undo history and zoom. It can open and save palettes and images, add the palette to the sprite file, make a palette from images, put the palette into image files, make optimized and grayscale palettes and gradients, set colors, remove repeated colors, add the other palette's colors, fit the image to the palette, sort by tone, swap and invert colors, and apply twelve color effects. It also has hue, saturation and RGB sliders with a live preview, the mask, the color picker, sending colors and selections between the two palettes, and Commit changes and Commit sprite changes (with the palette handling dialog).
- Run in engine can also run projects in Ikemen GO, and offers its log folder after the run.
- Backgrounds editor (stages, screenpacks and storyboards): every element of the background group picked in the Backgrounds menu is drawn at the current tick the way the engine draws it (scrolling by delta, velocity, sine waves, tiling, parallax, 1.1 scales, animations and blending), with the screen edges, the players' start positions and the timeline. A click selects the element on top, dragging moves it, and the selection shows its tile and window. Play (with Pause and Stop) runs the group at 60 ticks a second inside the screen, and the arrow keys move the camera inside the stage's bounds.
- The element panel edits the name, type, sprite or animation, masking, start, delta, velocity, ID, layer, link to the element before, tiling and spacing, transparency (with source and destination), parallax (width or x scale), Y scale, 1.1 scale start and delta, the window and its delta, and both sine waves. The Controllers panel edits the controller definitions (name, loop time, up to ten element IDs) and their controllers (name, type, values, X and Y, time). Backgrounds menu: Add, Remove, Duplicate, Play, Pause, Stop and the Controllers commands. The Organizer hides elements and changes their order. Each change only rewrites the keys it changes, as one undo step in the definitions text it shares with the Definitions editor.
- Screenpacks also open their select.def in the Definitions editor.
- Project > New: the Project template window lists the template scripts of each category (`scripts/project/<category>/<name>.lua`, with a .png or .svg icon). The Empty template that comes with the program asks for a character, stage, font or storyboard and opens a blank project of that kind in the Definitions editor. Its files only live in memory, made from the engine's blank files (data/engines/mugen/new), have no name until they're saved and don't go in the history. Project > Save asks for a name for each changed file in turn ("Save definitions as..."), and saving the definitions puts the project on disk. New projects without a name are called "Project 1", "Project 2" and so on.
- Project template scripts: wizards and pages, radio buttons, check boxes, labels, line edits, combo boxes, spin boxes and layouts, message boxes, FF.translate, FF.emptyProject and FF.projectFromFile (also as a copy, whose files stay unnamed and changed until saved), and each engine's lists of values (MUGEN.ProjectType).
- Project > Open from archive: opens the project in a ZIP file (its first definitions file), unpacked into a folder of its own that is removed when the project closes. Saving one of its files asks where, starting in the archive's folder. Nothing is written into the archive. The history remembers the archive.
- Project > Open single file: each file you pick opens as its own project ("Project 1" and so on) in the editor for its kind, saves where it is and stays out of the history.
- Project > Save as: the whole project, with your changes, is written to the folder you pick with the definitions file renamed, and you go on working from there.
- Project > Create backup writes a ZIP of the project's files, with your changes, into a "backup" folder next to it (`04.10.2026_10.32.40_pm_.zip`). Options > General > Make a backup before loading a project writes one (`..._Auto.zip`) every time a project is opened. Project > Load backup lists the backups in the Restore backup window, writes the one you pick over the project's files and then loads the project again.
- Options > General > Auto save: every few minutes, each changed file that has a name is saved where it is, quietly, and keeps its undo history.
- Options > General > Cache type: Memory keeps every sprite image it has read. Hard disk (low memory usage) keeps a few in each editor and in the emulator and reads the others again when they're needed.
- File watcher: a project file changed by another program is loaded again, asking first or not as Options > Messages > Reload watched files on modification says ("File modified"). Saves made by the program itself aren't reported.
- View > Organizer: rows can be dragged to a new place in every editor that has it (one undo step each).
- View > Organizer in the Animations, Sounds and Commands editors: their animations ("0 - Standing"), sounds ("0, 1") and commands (by name) move one, ten or all the way up or down, one undo step each. Organize automatically sorts animations by number and sounds by group and number. A double-click shows the item.
- Animations and Sounds > Import from another project: brings in the animations (with their comment line) or sounds of another open project, under new numbers picked in the list on the right, after the current one. For numbers already used it asks, replaces, skips or adds them anyway. Import sprites also brings the sprites the animations use that the project doesn't have.
- Tools > Export to HTML: a web page about a character or stage made from a layout (`data/engines/mugen/layouts/<kind>/<name>/`, with `!ff <key>!` placeholders). It has the details from the definitions, the e-mail, home page and comments you type in, the portrait, the standing animation as a GIF for each palette, and the commands you pick drawn with button and direction pictures (made for layouts that don't have their own). For stages it has a still picture and an animated GIF of the backgrounds, at the size, frame rate and length you pick. The page uses the character set the layout asks for.
- Tools > Script editor: write, open, save and run Lua scripts. The toolbar has New, Open, Save, Save as, Run and Save for translation, and the code editor highlights Lua. Run shows what debugOutput() and print() write in the output box, and the errors in the message list (double-click to go to the line) and in a "Script error!" box. On the right, the engine and the script type pick the folder whose scripts are listed (double-click to open one). The window remembers its place and size.
- Tools menu scripts: every .lua file in scripts/tool (and in an engine's scripts/tool) becomes a Tools menu item that runs the script and its main(). A "Quick action script" you can change comes with it.
- The Lua API (see the Lua scripting document): the FF functions for projects (projectCount, projectAt, currentProject, currentEngine, engineList, engineByName), FF.emptyProject and FF.projectFromFile opening their project right away, the lists of values (FF.Filter, FF.FileType, FF.Mode, MUGEN.ProjectType with the same numbers as Fighter Factory and so on), and classes for projects and their files, code documents and cursors, sprites, palettes, animations with their frames and contact boxes, sounds, archives, files and widgets.
- Save for translation writes a Qt Linguist file with the texts of a script's FF.translate calls. A script's own translation (`<name>_<language>.qm` next to it) is used when it runs.
- Breakpoints: Debug > Toggle breakpoint (on the code editor's current line), or a click on the strip left of the line numbers, marks a line. Debug > Add breakpoint... opens the Breakpoint window (file and line, function, memory address or frame, with enabled, condition, ignore count and one shot). The Debugger panel lists them with their state icon, number, function, file, line, address, condition and ignore count, and can edit, turn on, turn off and remove them.
- Emulator: the project runs inside the program in an engine that works like M.U.G.E.N, using the engine folder it's in (or the one picked in the panel). A character fights itself or another character from the engine folder on its stage, played with the keys set in Options > MUGENext. A stage or fight screen project is shown with the engine's character, a storyboard plays its scenes, and a motif shows the system screen picked in the panel (title menu, versus, continue, victory, win, survival results). The match follows the engine's rules: states and controllers, triggers and expressions, physics, hits, guarding, throws, reversals, helpers, explods, projectiles, pauses, and rounds with intros, KO, time over and win poses. Changes you haven't saved in the editors are used.
- Emulator screen: the stage's layers, the players, effects and sparks in sprite priority order with the engine's palettes (an SFF v1 character's pal1, RemapPal), palette effects (PalFX, AllPalFX, BGPalFX), after-images, transparency and screen effects. Also the fight screen from fight.def (lifebars, power bars, faces, names, timer, combo counters, win icons and the Round, Fight, KO and winner calls in its fonts), the KO slowdown, and View > Attack box and Collision box over the game. The mouse wheel zooms. Sounds play with the engine's channels and panning, and the announcer's from fight.snd.
- Emulator drawing: the camera zooms the way a stage's [Camera] zoomout, zoomin and startzoom say (each background element by its zoomdelta), and the Zoom controller moves and scales the view (pos, scale, lag, time). CameraZoom, GameWidth, GameHeight and the edge triggers follow the zoom, and the fight screen keeps its size. Shadows are drawn the way the stage's [Shadow] says (intensity, color, yscale, fade.range, xshear) under the players and helpers (with their shadowoffset, Offset and AngleDraw), under explods with a shadow and under projectiles with projshadow. AssertSpecial noshadow and globalnoshadow hide them. Reflections show when [Reflection] has reflect = 1 or an intensity. Explods turn around their x and y axes (xangle, yangle), seen in the engine's fixed perspective. Helpers, explods and projectiles with ownpal keep their palette when the owner uses RemapPal later, and take the one from remappal. Projectiles leave after-images (afterimage.time, length, timegap, framegap, trans and the palette effects).
- Emulator panel: Versus or Training, Self or Random enemy, rounds, round time, explod mode (M.U.G.E.N 1.0 or 1.1 rules, or by each character's version), debug info under the players, and the training options (dummy control Cooperative, AI with its level, or Manual; stance; auto guard; distance; button jam), which work while the match is running. Training fills life and power back up and nobody gets knocked out.
- Emulator debugging: every match is a debug session. It stops at breakpoints on [State] and trigger lines (with conditions, ignore counts and one shot), at frame and data breakpoints, and on Debug > Interrupt. Step into, over, out and frame go on from there. The line it stopped on opens with the current line marker. The Debug panel shows the values of the match and of each player (life, power, position, velocity, states, var, fvar and more), which can be watched in the Watch lists or get data breakpoints. The Debugger panel shows the call stack.
- Emulator: more of what characters other than Kung Fu Man use. HitDef's affectteam, chainID and nochainID, hitonce, p1getp2facing, forcestand, forcenofall, snap, mindist and maxdist, juggle points (StateDef juggle, air.juggle, nojugglecheck) and mugen.cfg's power multipliers. Also StateDef facep2, the ReversalDef spark and sound, Width's edge, DestroySelf's recursive and removeexplods, Pause's endcmdbuftime, RemapPal of every palette, MakeDust's spacing, GameMakeAnim's random, PlaySnd's volumescale, Explod's angle, helper names and ownpal, and AssertSpecial noBG, noFG, nobardisplay and nokoslow. New triggers: Name, P1Name to P4Name, AuthorName, StageVar, PlayerIDExist, IsHomeTeam, TeamMode and HitVel, and M.U.G.E.N 1.1's screen and camera triggers (the edges, CameraPos, CameraZoom, ScreenWidth, ScreenHeight, GameWidth, GameHeight). HitDefAttr still reads an attack after it hit, ScreenPos Y counts from the top of the screen, Const gives sizes as whole numbers, and wrong variable numbers, animation elements and redirection IDs give bottom.
- Debug > Start on Engine (Windows): the project runs in WinMUGEN the same way Run in engine runs it, with the run configurations from Options > MUGENext, and the debugger watches the engine while it runs. The Debug panel shows the game's values and each player's and helper's (life, power, position, velocity, states, ctrl, palette, multipliers, var, fvar, sysvar, sysfvar and more). data/engines/mugen/debug.xml says where to find them, and the ones it leaves empty show N/A. Interrupt and Continue pause and resume the engine, Step frame runs one frame, and a breakpoint inside a state stops when one of the project's players or helpers goes into that state, with the current line on its [Statedef]. Frame and data breakpoints, conditions, ignore counts and one shot work like in the emulator. Step over, into and out need the emulator. Stop closes the engine and removes its copy, and Restart starts it again.
- Emulator hits: a hit or guard against an opponent in the corner pushes the attacker back by the HitDef's ground.cornerpush.veloff (or its air, down, guard and airguard versions, with the engine's defaults). A lying opponent knocked up by down.velocity only bounces when it lands if down.bounce is set. ForceFeedback is read and does nothing, since there's no rumble.
- Emulator music: the stage's [Music] bgmusic plays during the match (with bgmvolume or bgvolume, bgmloopstart and bgmloopend, and the music volume from mugen.cfg) and pauses while a player asserts nomusic. A motif's title, versus and victory screens play their [Music] bgm, and a storyboard's scenes play their bgm with its loop, volume and loop points. WAV, OGG and MP3 files play from the engine folder, and MIDI stays silent.
- Emulator stages made for another size ([StageInfo] localcoord, like 1280,720) are scaled to the game's size. A stage wider than the screen is drawn from the bottom of the screen, raised by its overdrawlow, and a taller one is cut the way cuthigh and cutlow say. [StageInfo] xscale and yscale scale the backgrounds.
- Emulator characters made for another size ([Info] localcoord, like 1280,720) keep their own units, the same as in M.U.G.E.N. Positions, distances, velocities and sizes are converted to the game's units when they meet other characters'. A redirected trigger answers in the units of the character that asked, and a character thrown into another one's states uses that one's units. Its sprites, contact boxes, lifebar face and portraits are scaled to the game.
- Opening a project shows the "Loading project..." window over the main window, counting up in percent until the project shows, like Fighter Factory. No panel pops up as a window of its own while it loads. Dialogs have the help button (?) and their own titles like in Fighter Factory, and the windows keep the light title bar whatever color mode the system uses.
- Toolbars stay where they were dragged to (top, bottom, left or right, first or second row) the next time the program starts.
- Background tasks: loading and saving big sprite and sound files no longer freezes the window, and the progress shows in the status bar (click it to list the running tasks). Closing the program or running in the engine waits for them. Auto save can save in the background.
- Run in engine plays a character, stage or motif that's already in the engine folder right where it is, without a temporary copy (after saving it).
- Quick search in the graphic editors: find a sprite or sound by "group,number", or an animation by number or name.
- Help > Reference Documentation opens the program's own guide (editors, emulator, tools, shortcuts) in the browser.
- Downloads: a Windows installer that doesn't need admin rights and a portable ZIP, a Linux AppImage and a macOS disk image.
- Sprites > Change image asks whether to crop the new image's see-through border, which palette it gets (the Palette window), and for a linked sprite whether every copy gets it. Save image changes asks the last question too. Options > Messages remembers the answers.
- Options > Messages > Can't save empty sprite list, Can't save 8-bit sprites without palette and Can't save empty sound list stop those saves. When they're unticked, sprites without a palette can get a gray palette before saving.
- Options > Graphics: Invert sprite axis (the Sprites editor's axis boxes show the image's offset from the axis), Contact box over axis and Colors fit available space (the Advanced palette editor's grids fill the window's width).
- Project > Open from archive opens RAR files (RAR 4 and 5) as well as ZIP files, through the RAR extension, and the Archive class in scripts reads them too. Extension plugins can add other formats.
- Options > Graphics > Renderer: with Automatic or OpenGL, the Sprites, Animations and Backgrounds workspaces, the image editor and the emulator are drawn with OpenGL (DirectX also uses OpenGL, since Qt 6 has no ANGLE). Native painter draws them in software. If the OpenGL driver crashed before the first frame, the next start uses the native painter. The status bar shows which renderer is used.
- Classic and Ultimate icon sets with their own pictures (from the Tango theme) for the icons those presets change, like Fighter Factory: file actions, clipboard, the sprite, animation and sound editors, contact boxes and palette tools. The other icons are the Nuvola ones.
- Windows: each project tab gets its own preview in the taskbar, showing the character's big portrait. Clicking it shows the tab, and closing it closes the project.
- The program can be translated. Qt's lupdate collects every menu, action, panel and message text (see the Contributing document).

### Fixed

- Saving a big sprite or sound file on a busy computer no longer makes the program ask whether to load it again. The file watcher now waits until a save running in the background is done.
- Run in engine also copies the other files a character's definition names, like the palette files of WinMUGEN characters, which wouldn't load without them.
- Keyboard, the same as in Fighter Factory: clicking a selector bar (sprites, animations, frames, sounds, backgrounds, palettes, onion skin) gives it the keys. Right or Up and Left or Down go through the items, PgUp and PgDn jump by 10, and Home and End go to the ends. The Sounds tool buttons hand the keys to the waveform, where Left and Right move the cursor (and pause), Shift+Left and Shift+Right move the end of the selection, and holding Ctrl uses the Move view offset tool. Picking a code editor, the Backgrounds editor or the Emulator gives it the keys, and so do the image editor's tools (the canvas), Backgrounds Play and the start of a match. Enter on a code tree entry goes to it, like a click.
- The side panels fit their width like in Fighter Factory. Their controls share the panel's columns evenly and get smaller when there isn't enough room (long text is cut), and spin boxes keep room for the value next to the arrows. Before, the controls ran past the right edge and the panel scrolled sideways.
- Every theme is easy to read. The recent projects on the Welcome page (dark blue on the dark themes before) use the theme's text color on raised buttons like in Fighter Factory. Open code editors take the colors of a theme picked later. The rulers of the graphic workspaces and the Offset viewer, the animation timeline and the waveform follow the interface style (light on the light styles, dark on the dark ones), and the waveform uses the color set's sound wave color.
- The Sprites and Animations workspaces and the image editor are drawn over the color set's workspace gradient (Background start and end) the way the color sets say (they used a fixed dark gray before). The Script editor's background and text follow the color set like its highlighting does.
- Setting the Sounds editor's Current sample moves the cursor and pauses, like in Fighter Factory.
- The first run window draws each theme's picture in that theme's own colors (Ultimate's was shown dark).
- The snippet editor uses the code font from Options > Code, Options > Interface's scale works over its whole range (0.2 to 10), and the line between a stereo sound's channels shows on every theme.
- The PalFX editor's preview colors a sprite the same way the engine and the emulator do ((color + add) x mul / 256 after the weighted gray of Color), so the preview shows what the match will.
- Zooming with a touchpad or a smooth scrolling wheel works in the graphic workspaces, the image editor, the waveform and the emulator (small scroll steps add up).
- The emulator's status bar names the renderer that's used, and the yellow note in Options > MUGENext has the right style.
- Speed: the emulator reads the players' keys and its drawing options once (it read them on every tick before), and the status bar no longer searches the window every time the mouse moves.
- Throw creator: numbers typed one after another in Group or Index undo together, the way typing text does in Fighter Factory (the first key, then the rest).
- Same as Fighter Factory: a pasted image editor layer is named after the layers under it ("Layer 1" over one layer), Decompress on load stays on for SFF v1 files, Sounds > Save only works in the Sounds editor, and undo and redo in the image editor leave the selection as it is.
- Sprites editor, the same as in Fighter Factory: Group and Index change the sprite right away when you click an arrow or press a key, or press Enter after typing (they waited until you left the box before). View turns off Secondary cross and Extra cross, which only the Animations editor draws. Centralize origin puts the axis in the middle of the whole workspace, rulers included.
- The code editors now work like Fighter Factory's: the first Down in a completion list picks the current word, Shift+Tab types a tab (over a selection too), and Auto-format respaces the trigger lines of every controller, Null too.
- A double-click on a run configuration in Options > MUGENext doesn't open anything, the same as in Fighter Factory (Edit opens it).
- The Definitions trees of stages, screenpacks, storyboards and fonts look like Fighter Factory's: each background family under one entry ("BG", "Title Backgrounds", a storyboard's "BG0"), animations as "Animation 180" (in a storyboard "10 - \<its comment>"), and a font's "FNT V2" and its type.
- The Emulator's Start button, the Palettes switch in the organizer and the four buttons of the Sprite explorer show icons like in Fighter Factory (the Sprites or Animations editor's ones, with their names as tooltips). Their text used to be cut off. Start is off while the match runs (Stop is in the Debug panel).
- The palettes of SFF v1 and v2.0 files have their first color see-through and the others solid, like in Fighter Factory. The fourth color byte in M.U.G.E.N 1.0's files isn't alpha (Kung Fu Man's palettes looked empty in the Palettes panel and the Advanced palette editor, and its Save image wrote them see-through). Files that weren't changed still save byte for byte.
